# فضاجو — بسته ۳: طرح زیرساخت سرور ایرانی (بدون خرید و بدون اجرا)

این بسته بر اساس فایل Fazajoo_FOR_CHATGPT(10).zip آماده شده است. فقط دو فایل نمونه و این راهنما را به پروژه اضافه کنید؛ هیچ فایل موجودی جایگزین نمی‌شود.

## وضعیت
- هنوز دامنه یا VPS خریداری نشده؛ هیچ تنظیم واقعی DNS، گواهی HTTPS یا رمز عبوری در بسته وجود ندارد.
- فایل‌های `*.example` را مستقیماً فعال نکنید. باید نام دامنه، کاربر لینوکس و مسیر استقرار با مقادیر واقعی جایگزین شوند.
- این بسته فقط طرح استقرار است، نه تأیید آمادگی نهایی امنیتی و نه استقرار واقعی.

## طرح پیشنهادی برای فاز اول
- VPS در دیتاسنتر داخل ایران؛ Ubuntu LTS؛ 2 vCPU، 4GB RAM، SSD حداقل 60GB برای شروع ارزیابی؛ امکان ارتقا و تهیه snapshot/backup.
- Node.js سازگار با Vite 8 و پکیج‌های پروژه؛ نسخه دقیق پس از بررسی lockfile و سرور تعیین شود.
- PostgreSQL روی همان VPS در فاز اول؛ اتصال فقط از loopback؛ بکاپ مستقل خارج از VPS و آزمون بازیابی.
- NGINX برای ارائه فایل‌های `dist/` و reverse proxy به API و Socket.IO.
- سرویس systemd برای بک‌اند؛ نیازی به PM2 همزمان نیست.
- فضای فایل‌های کاربر در Arvan Object Storage؛ SMS با سرویس پیامکی تنظیم‌شده.

## مواردی که قبل از خرید باید بررسی شوند
1. دسترسی پایدار کاربران ایران و امکان اتصال از اپراتورهای مختلف؛ IP ایرانی و دسترسی SSH.
2. ترافیک ماهانه، پهنای باند، فضای SSD، هزینه بکاپ، snapshot و ارتقا.
3. امکان دسترسی به registry بسته‌های Node و به‌روزرسانی‌های Ubuntu از سرور؛ مسیر نصب آفلاین/میرور در صورت محدودیت.
4. سیاست پشتیبانی، SLA و روش بازیابی در خرابی.
5. دامنه قابل ثبت و مدیریت DNS و صدور SSL.

## فایل‌های نمونه
- `deploy/nginx/fazajoo.conf.example`: کانفیگ HTTP اولیه برای دو زیر‌دامنه، پشتیبانی از React Router و Socket.IO. HTTPS هنوز فعال نیست.
- `deploy/systemd/fazajoo-backend.service.example`: اجرای backend با `NODE_ENV=production` و راه‌اندازی مجدد خودکار.

## نکته بسیار مهم درباره HOST و TRUST_PROXY
- برای معماری تک‌سروری NGINX و Node، مقدار امن‌تر `HOST=127.0.0.1` در `backend/.env.production` است تا پورت 6060 مستقیماً از اینترنت قابل دسترسی نباشد.
- `TRUST_PROXY=1` فقط وقتی درست است که دقیقاً یک reverse proxy مورد اعتماد جلوتر از Express قرار داشته باشد و دسترسی مستقیم به backend بسته باشد.
- این تنظیمات را در فایل محلی توسعه تغییر ندهید.

## بعد از خرید (بسته‌های ۴ و ۵)
1. ساخت کاربر محدود لینوکسی، نصب نسخه‌های سازگار Node/PostgreSQL/NGINX و بستن پورت 6060 در فایروال.
2. نصب وابستگی‌ها با lockfile، انتقال پروژه، ساخت DB و اجرای migrationها با بکاپ و کنترل ترتیب.
3. ایجاد `backend/.env.production` واقعی فقط روی سرور با مجوز محدود؛ هرگز در GitHub یا ZIP ارسالی قرار نگیرد.
4. تنظیم DNS دامنه و API، صدور HTTPS، سپس تنظیم CORS و `VITE_API_BASE_URL` و ساخت مجدد فرانت‌اند.
5. فعال‌سازی NGINX پس از بررسی `nginx -t` و تست Socket.IO، API و refresh مسیرهای React.
6. اجرای تست‌های واقعی از داخل ایران و بررسی خطاهای امنیتی/پایداری.

## نکات بررسی کد فعلی
- `backend/src/server.js` روی HOST و PORT خوانده‌شده از config گوش می‌دهد و Socket.IO را به همان HTTP server متصل می‌کند.
- `backend/src/config/env.js` در صورت `NODE_ENV=production` فایل `backend/.env.production` را می‌خواند؛ systemd این متغیر را صریح تنظیم می‌کند.
- `backend/src/db/pool.js` با PostgreSQL ارتباط برقرار می‌کند.
- `backend/.env.production.example` در ZIP فعلی HOST=0.0.0.0 دارد؛ در معماری پیشنهادی تک‌سروری به 127.0.0.1 تغییر دهید.
- فرانت‌اند Vite باید پس از تعیین دامنه با `VITE_API_BASE_URL` واقعی build شود.
- فایل‌های .env واقعی را وارد Git نکنید. قبل از commit، `git status` را بررسی کنید.

## نصب فایل‌ها در پروژه ویندوز
فقط پوشه `deploy` را از این ZIP به ریشه پروژه `Fazajoo_MAIN` کپی کنید. فایل‌های `.example` تا زمان خرید سرور صرفاً مرجع هستند.
