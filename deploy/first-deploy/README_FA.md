# فضاجو — بسته ۴: آماده‌سازی اولین استقرار (مرحله ۱، بدون سرور)

این بسته بر مبنای ZIP لحظه‌ای `Fazajoo_FOR_CHATGPT(20261009-011019).zip` تنظیم شده است. بسته ۳ (`deploy/README_FA.md`، نمونه NGINX و systemd) در پروژه موجود است. **این بسته هنوز استقرار واقعی نیست**؛ تا زمانی که سرور فعال نشده، فقط ابزار بررسی اولیه و دستورالعمل ایمن فراهم می‌کند.

## وضعیت فعلی
- سرور پارس‌پک irCloud5 با Ubuntu 24.04 انتخاب شده، اما خرید/فعال‌سازی هنوز تأیید نشده است.
- بک‌اند Node/Express + Socket.IO و PostgreSQL و فرانت React/Vite است.
- دو فایل lock برای نصب قابل تکرار موجودند: `package-lock.json` و `backend/package-lock.json`.
- فایل‌های واقعی `.env.production` و رمزها نباید در ZIP، Git یا گفتگو ارسال شوند.
- **اسکریپت بررسی** فقط اطلاعات عمومی سیستم را می‌خواند؛ چیزی نصب یا تغییر نمی‌دهد.

## مرحله ۱: پس از فعال‌شدن سرور
از پنل پارس‌پک IP و روش ورود SSH را بگیرید. از ویندوز PowerShell با SSH به سرور متصل شوید. پس از ایجاد یک کاربر غیر root دارای sudo، اسکریپت `preflight.sh` را به سرور انتقال داده و اجرا کنید:

```bash
bash preflight.sh
```

نتیجه را بدون اطلاعات ورود برای بررسی ارائه دهید. اگر برنامه‌ها هنوز نصب نباشند، نمایش MISS طبیعی است.

## مرحله ۲: کارهای بعدی — فقط پس از بررسی خروجی مرحله ۱
1. به‌روزرسانی سیستم، نصب نسخه سازگار Node.js (Vite 8)، PostgreSQL، NGINX و Git.
2. ایجاد کاربر محدود و مسیر `/var/www/fazajoo` با مالکیت مناسب؛ بررسی روش دسترسی به مخزن خصوصی GitHub از سرور ایران.
3. انتقال نسخه مشخص از شاخه `main`؛ اجرای `npm ci` در ریشه و `npm ci --omit=dev` در backend. فرانت‌اند هنگام build به devDependencies نیاز دارد.
4. ایجاد دیتابیس و کاربر اختصاصی PostgreSQL با دسترسی حداقلی و اتصال فقط از loopback.
5. **بازبینی ترتیب migrationها** قبل از اجرای هر SQL: پروژه `schema.sql` و چند migration مجزا دارد. اجرای کورکورانه همه migrationها ممکن است داده موجود را خراب کند. قبل از هر migration بکاپ و آزمون بازیابی ضروری است.
6. ساخت فایل `backend/.env.production` فقط روی سرور؛ `HOST=127.0.0.1` و `TRUST_PROXY=1` برای معماری NGINX تک‌پراکسی، با بستن دسترسی مستقیم به 6060.
7. آماده‌سازی سرویس systemd و NGINX با الگوهای بسته ۳. تا زمانی که دامنه و TLS فعال نشده‌اند، اطلاعات واقعی کاربران وارد نشود.
8. بعد از تعیین دامنه، ساخت فرانت‌اند با `VITE_API_BASE_URL` واقعی و HTTPS در بسته ۵؛ تست اینترنت ایران در بسته ۶.

## نکته‌های مهم
- دستورهای بالا **چک‌لیست هستند نه دستور اجرای خودکار**. برای هر مرحله باید خروجی مرحله قبل بررسی شود.
- اگر قبلاً دیتابیس محلی حاوی داده‌های مهم دارید، انتقال داده تصمیم جداگانه‌ای است؛ هیچ دیتابیسی را با `schema.sql` بازنویسی نکنید.
- فایل `backend/.env.production.example` فعلاً `HOST=0.0.0.0` دارد. در سرور تک‌ماشینه با NGINX آن را در **فایل واقعی روی سرور** به `127.0.0.1` تغییر دهید.
- هزینه‌ها و امکان تغییر منابع سرور را باید در پنل پارس‌پک بررسی کرد؛ این بسته تغییری در سفارش نمی‌دهد.

## نصب بسته در ویندوز
فقط پوشه `deploy/first-deploy` را به ریشه پروژه کپی کنید. هیچ فایل فعلی جایگزین نمی‌شود. پس از بررسی، فایل‌های جدید را commit/push کنید. هیچ فایل رمزدار را commit نکنید.
